issues #440, #450 — dev proxy for WAF-protected hosts

Checks the acceptance items that cannot be unit tests, because a bot challenge keys on Origin and only a browser at localhost sends the failing one. This page calls hic.setUrlMapper(devMapUrl) on load — the one line a host app adds in development. See docs/adr/0001-dev-proxy-for-waf-protected-hosts.md.

1. The rewrite is host-scoped — not run

No network. Confirms the registered mapper routes ENCODE through /__hic-proxy/ and leaves every other host in the session-file set fetching directly, so a real CORS or permissions problem still surfaces here as it would in production. 

—

2. The proxy returns the redirect — not run

Fetches one byte range through the proxy with redirect: 'manual', so the redirect is visible rather than followed. Passes when the proxy answers 307 with a Location pointing at a different host: the map bytes come from S3 straight to the browser, never through Node. 

—

3. An ENCODE map loads from localhost — not run

The acceptance criterion. The same URL that fails with a bot challenge on master loads through hic.createBrowser. Watch the network panel: the /__hic-proxy/ request is the redirect only; every range request that follows goes directly to S3 as 206 Partial Content. 

—

4. ENCODE-hosted tracks load, and stay out of the session — not run

Issue #450's acceptance criteria. Loads a bigWig (1D, read by igv's own loaders) and a .bedpe (2D, read by juicebox) from the same challenged host onto the map from probe 3, then checks browser.toJSON(). Both must render, and neither may contribute a /__hic-proxy/ path to the session — a session saved in development has to load in production. Run probe 3 first.
