Per-browser viewport size — issue #477

The unchecked per-browser scoping box on #549. Before #477, --hic-viewport-width/height were written to document.documentElement, so every browser on the page shared one size and the last one to lay out won. They are now written to each browser's own rootElement (js/layoutController.js setViewportSize), from config.width/height at construction time (js/hicBrowser.js). Nothing in the app resizes a browser afterwards — there is no resize gesture, which is why this page and not a click-through in juicebox-web.

Four browsers are built in order, one at a time, because the old bug was order-dependent: whoever wrote last won. Three go into embed A — the juicebox-web shape, several browsers in one container — and the fourth into a second embed, which is how #477 was originally framed. The unsized browser is built last, so under the old behaviour it would have inherited 400px from the browser before it; it must fall back to the 640px stylesheet default instead.

The gate is the resolved custom property on each browser's rootElement — that is literally what #477 moved. Measured viewport width is gated with it: with no 1D tracks loaded, viewportElement's width works out to exactly the viewport width. Measured height is reported but not gated, because the viewport's height is handed out by the surrounding flex layout rather than set from the variable directly.
