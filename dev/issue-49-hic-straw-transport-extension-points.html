hic-straw #49 — transport extension points

Verifies the acceptance item that cannot be a unit test: a bot challenge keys on Origin, which node never sends, so this must run in a browser at localhost. Requires hic-straw ≥ 4.0.0 — package.json is pinned to github:aidenlab/hic-straw#master on this branch and must be repinned to #v4.0.0 once that tag is cut.

1. Response detail — not run

Reads a blocked ENCODE URL through Straw and inspects the thrown error. Passes when err.headers.get('x-amzn-waf-action') is captcha — the signal that used to die inside hic-straw. Also confirms err.message is non-empty, which statusText alone is not over HTTP/2. 

—

2. mapUrl composition — not run

Supplies a consumer mapUrl against a Dropbox URL that does not exist, and reads the physical URL back off err.url. Passes when the failed fetch shows both rewrites in the right order: hic-straw's default Dropbox rule applied first (www.dropbox.com → dl.dropboxusercontent.com), then the consumer rule on top. A consumer supplying mapUrl must not silently switch off the default rules. 

—

3. Through juicebox.js — not run

The same blocked URL through hic.createBrowser, i.e. the path a real application takes. Shows what juicebox.js surfaces to a user today. This probe is informational: juicebox.js has no interpretation layer yet — that is the dev-proxy work in this repo's docs/adr/0001-dev-proxy-for-waf-protected-hosts.md. What it establishes is that the response detail survives the trip up through juicebox.js and is available to build that layer on.
