Parallel track load (#663, #664)

Each button loads a set of tracks into the map below. Good tracks load; bad tracks point at a missing object or an unresolvable host. What to check, per ADR-0017 decision 6:

  • Every good track is laid out even when a bad one is in the same set.
  • Tracks lay out in the order they were listed, whatever order they finish in. The RefSeq genes file is listed first and is the slowest to arrive.
  • Failures raise one alert naming each failed track — or, for loadTracksOrThrow, no alert and one rejection, shown in the box below.
  • A single bad track alerts as it always has: Error loading track NAME: reason.

And per decision 3, a pending track is a placeholder row (#664):

  • Every 1D track shows a row with its name and a small spinner the moment a button is pressed, in the position it ends up in. 2D tracks get no row.
  • A row becomes the track as it arrives; a bad track's row is removed.
  • The large spinner in the centre of the map never shows for a track load, including during Restore once the map itself has loaded.
  • The map is not resized as tracks arrive — only when a bad track's row is removed.

And per decisions 4 and 8, a pending track can be dismissed (#665):

  • A placeholder row has an × where a loaded track has its gear; clicking it removes the row.
  • A dismissed track never appears when its load finishes, and a dismissed bad track raises no alert.

The box lists the tracks laid out after each load, in gutter order. Tracks accumulate; Reload page starts clean.
