the shape, not the backlog — companion to architecture-review.html

What this document is for

The review answers what to fix next. This answers what the thing is becoming: every module that is or will be deep, its interface, what it hides, and the seam it sits on. Read the review to scope a candidate; read this to know where the candidate lands.

It is a snapshot of a moving target, and it says so on every card. Six candidates have landed, one is underway, four are ahead. Each card carries the state of that module today and the delta the next candidate applies. Cards do not describe a finished architecture, and drawing them as if they did would be the lie that makes this document useless.

Vocabulary is CONTEXT.md § Architecture vocabulary — module, interface, depth, seam, adapter. Depth here means leverage at the interface: behaviour exercisable per unit of interface learned. Not a line-count ratio.

Reading the colours honestly

State is drawn "planned" even though the chokepoint landed. The chokepoint is real and enforced; what has not landed is closing the back door beside it. A module is only green here when its whole card is done.

HICBrowser is white, not green. Two candidates have already carved pieces off it and it is still 1235 lines with the widest interface in the repo. It is white because it is not a deep module and no single candidate makes it one — it gets smaller as 6, 9 and 10 land, and that is the plan.

① Embed — the published door

BrowserRegistry

Landed · candidate 4 · #476, #478–#483

js/browserRegistry.js · 429 lines · ADR-0004

Interface

initRegistry(container, config) → registry

add · select · delete · deleteAll · dispose

toJSON · restoreSession · presentAlert · sync

Hides

The browser list and which is current. The sync group. The selected gene. The alert dialog and its container. Slot release and reclaim. Teardown ordering across peers.

Seam

One registry per container element. This is the unit of isolation that lets two embeds coexist on a page — the thing that made the old page-scoped singletons a bug rather than a simplification. Two adapters exist in practice (two containers on one page), which is what makes it a real seam rather than a hypothetical one.

Depth verdict — deep. A host learns one function and gets isolation, lifecycle, selection, sync and serialization. The deletion test passes hard: remove it and all of that reappears as module-level state in createBrowser.js, which is exactly where it used to live.

Loose end: --hic-viewport-* CSS variables are still page-scoped, so two embeds cannot have different viewport sizes — #477, open. The seam holds in JS and leaks in CSS.

hic namespace

Shallow on purpose

js/index.js · js/init.js · ADR-0003

Twelve exports, almost all of them one-line delegations to a registry. This is correct and should stay that way. The namespace is a published contract, and a contract's job is to be stable, not deep. Depth belongs behind it.

The interesting fact about this tier is what it does not export: HICBrowser. Hosts get instances from init(), so the entire browser-instance surface is public in practice and declared nowhere except js/publicApi.js. The deletion test is not valid against js/ alone — check the manifest first.

② Browser — the hub

HICBrowser

Partly carved · candidates 3 & 8 landed · 6, 9, 10 still to come

js/hicBrowser.js · 1235 lines · the largest module on this map after nvi.js

This is the one module the redesign does not turn into a deep module, and it is worth being explicit about why. HICBrowser is the hub every tier reaches through. Its interface is not a set of methods anyone designed — it is the accumulated public surface two shipped host apps already depend on. You cannot shrink it by choosing to; you shrink it by moving behaviour out from under it into modules that are deep, and letting the members that only forwarded disappear with the thing they forwarded to.

Already moved out

Candidate 3 — browserUIManager.js and renderCoordinator.js deleted, 14 notify* forwarders gone.

Candidate 8 — four teardown verbs became two; dispose() is now symmetric with the constructor at both browser and registry level (ADR-0005).

Still to move out

Candidate 6 — the 10 state accessors, which the code itself documents as bypassing validation. Three plain fields survive.

Candidate 9 — config defaulting, currently applied in the constructor and in init.

Candidate 10 — three load paths that reach back into browser.userInteractionShield, contactMapLabel, browser.genome, tracks2D and a raw document.querySelector.

What "done" looks like here: not a target line count — candidate 3's member-count target was retired rather than met, on purpose. Done is when every remaining member either holds browser-scoped identity or is on the manifest because a host uses it.

BrowserCoordinator

Kept deliberately · ADR-0002

js/browserCoordinator.js · 445 lines

Interface: ~17 on* methods, plus addCallback(name, fn) — the host extension point. Hides: which widgets, rulers and views need refreshing for each kind of change, and in what order.

Depth verdict — medium, and that is the ceiling. The interface is wide because the set of things that can change is wide; each method is genuinely deep in the small (one call refreshes everything affected). ADR-0002 records the decision: deleting it pushes the fan-out back into HICBrowser, which is the thing this whole tier is trying to empty. Not on the table.

EventBus

Landed · candidate 2 · #414

js/eventBus.js · 135 lines

The card was titled "delete the event bus" and the bus was not deleted. Spacewalk subscribes on the per-browser one. What landed instead: eight dead subscriptions, three unreachable receiveEvent methods and the forged event literals are gone, and the bus finally has an unsubscribe.

Depth verdict — shallow, and correctly so. Both buses now carry zero internal traffic. They exist as pure consumer surface. That is a legitimate shape for a module to have, and it is only visible once you look outside js/. This card is the reason every card in the review carries a Consumer impact block.

③ State — the chokepoint

State

Chokepoint landed (#411, #499) · back door still open — candidate 6, confidence strong

js/hicState.js · 545 lines · docs/state-manipulation.md · ADR-0006

This is the exemplar. If you want to know what a deep module looks like in this codebase, read this one. Seven fields fully and unambiguously specify the view. Everything else the user sees is a projection computed on read.

Interface

One chokepoint — setView(chr1, chr2, x, y, zoom, pixelSize, …). Every canonical mutation goes through it.

Eight translators — panShift, updateWithLoci, setWithZoom, panWithZoom, zoomBy, recenterByPixel, setChromosomesView, sync. Each converts one domain's input into chokepoint arguments.

One projection — getLocus(dataset, viewDimensions). Never stored, because view dimensions change without any mutation.

Hides

XY clamping against dataset extent. The pixelSize cap at 128. The chr1 ≤ chr2 transposition — all four values atomically, which is why callers never order their arguments. Resolution- and chromosome-change detection, so change flags are honest. BP↔bin conversion.

The back door — what candidate 6 closes

StateManager.setState writes canonical state without passing the chokepoint: it floors, but does not cap and does not clamp. Session and URL restore go in that way. Ten HICBrowser accessors take the same route, and the code documents that they bypass validation.

Target shape: StateManager (220 lines, 8 of 10 methods pure get/set) folds into State; restore becomes restoreFrom, a translator like every other one, validating against the loaded dataset before it reaches setView.

Note the one deliberate exception that survives: bulk replacement. Session and URL restore replace the whole State object rather than mutating it, because at restore time there is nothing to translate relative to. The constructor transposes as belt-and-braces, which on canonical state is a no-op — and that no-op is what makes save → restore the identity.

④ Session & config — decode, then normalize

Two stages, not one, and the line between them is the most carefully drawn seam in the codebase (ADR-0006 decision 8). Decoding turns a wire format into a session document and is the only stage that knows a format exists. Normalizing turns a session document into one every loader can consume. Format knowledge never crosses into normalize.

Session codec

Landed · candidate 5 · #499–#509 · ADR-0006

js/sessionCodec.js · 950 lines

Interface

decodeSession(input, { loader }) → session document

Plus WIRE_FORMATS: an ordered array of adapters, each a pair of "does this input carry my format?" and "decode it into the shared context." Adding a fifth format is adding an entry.

Hides

v0 vs v1 sniffing. Compressed prefixes. The 7-token and 9-token state ladders, the 3- and 4-token track strings. Which branch a given input takes. The version field — stamped by the encoder, taken off by the decoder, never seen by restoreSession.

Seam · and why this one is load-bearing

The wire format is a contract with users, not just host apps: a link pasted into mail or a paper years ago must still decode. test/data/wireFormatCorpus.js holds one fixture per format and per decoder branch; test/testDecoderGolden.js snapshots what today's decoder makes of each. Those snapshots are the compatibility contract in executable form — a snapshot that moves is a change to the wire format until shown otherwise.

The corpus pins the accepted set, not the sent set. Links published outside the three repos and the docs have never been sampled; that gap is a decision, not an oversight (#509, closed).

Depth verdict — deep, and the network came out. The decoder is pure and driven from string literals; I/O is an injected loader (#505). That is what made it safe to change, and it is the pattern the next module inherits.

normalizeSession / normalizeConfig

Underway — you are here · candidate 9 · #531–#535 landed, #536 open

js/normalizeSession.js · still to draw from js/hicBrowser.js (constructor, init), js/dataLoader.js

The module now exists, and it is the one you are still building. No file yet states what a config contains: several modules each interpret a subset and apply their own defaults, which is how the four entry paths silently diverged. All three divergences below are closed.

Today — several readers, no schema

syncDatasets is honoured by createBrowserList and absent from createBrowser. Resolved at session level in normalize — #533.

fixDefaults runs on the URL path only — restoreSession skips it. Moved to normalizeSession.applyTrackDefaults, which every door meets — #533. What #525 still asks is whether forcing every track to COLLAPSED is right at all; it is no longer a disagreement between paths.

Normalization runs inside browser creation, and the same document meets the stage twice — once in restoreSession, again in createBrowserList. Lifted to the entry: two doors, BrowserRegistry.restoreSession and createBrowser, and nothing below them normalizes — #535.

URL-shortcut expansion runs twice — once on the URL path, again in restoreSession. Both copies deleted; the survivor is normalizeSession.expandUrlShortcuts, so the two doors that never expanded now do — #534.

Target — normalize once, at the entry

normalizeConfig(raw) → resolved config

Pure. Every default in one place, one schema, testable with object literals. Downstream consumers read fields — none of them default, none of them validate (#536).

Every entry path — hic.init, the query path, restoreSession, createBrowser — passes through it exactly once, and they agree. createBrowserList is no longer one of them: it builds browsers from a session its caller resolved (#535).

Why this one is safe to do now

Candidate 5 stopped exactly at this edge on purpose — shipping the normalize move with it would have doubled the blast radius on hic.init, the most-used public surface. What 9 inherits that 5 did not have: a golden-file snapshot over the whole wire-format corpus, already built and already green, plus test/testConfigGolden.js from #531, which pins what each entry path resolves to today. Normalization changes are exactly the kind that move decoded output, so every moved fixture has to be one you can explain.

Constraint the interface has to respect

A resolved config is not a copy. Every normalizer rewrites the host's own object in place, so the host's config and browser.config are one object — and juicebox-web reads it back (ADR-0003). A normalizeConfig that returns a fresh object is a breaking change to an observable surface, however much cleaner it is. Decide that deliberately.

⑤ Data access

DataLoader

Planned · candidate 10 · ports & adapters · this is the live-map seam

js/dataLoader.js · 476 lines

Three near-clones today. loadHicFile (121 lines: shield · label · spinner · Dataset.loadDataset · Genome · state ladder · nvi lookup · sync · notify ×5 · try/catch/finally). loadLiveContactMap (55 lines, with the state ladder duplicated). loadHicControlFile (47 lines, with a finally and no catch).

Target: loadMap(source, role) — one interface, with the .hic file and the live contact map as source adapters rather than parallel functions.

Why this is the hardest card on the map

The seam spans three repos. The core live-map work lives in hic-straw, not here; juicebox.js holds a thin adapter, and Spacewalk is why it exists. The live map is deliberately disguised as a .hic dataset — same Dataset, same render path, same canonical state — and the disguise holds everywhere except two places: imageTileCore.autoThreshold takes the 75th percentile and clamps to 1 for live maps, and loadLiveContactMap is its own load path rather than a parameter to the file path. Designing this interface means deciding which of those two is a genuine variation and which is an expediency to collapse. That is a real design question, not a mechanical refactor — it is the one candidate that would benefit from being prototyped before it is specified.

URL mapper + dev proxy

Landed · ADR-0001 · has an expiry condition

js/urlMapper.js · dev-proxy/

Interface: setUrlMapper(fn), registered once by the host, unset in production. Hides: that a URL is rewritten in three different places for three reasons — handed to hic-straw as config.mapUrl for a .hic read, applied at the fetch for a 2D annotation, and written into the config for a 1D track because igv reads those through loaders juicebox cannot reach into.

The library cannot detect dev mode itself — consumers get a production-baked dist. That is why the seam is a host-registered function rather than an environment check.

Two unrelated gates sit behind this: the bot challenge (AWS WAF at ENCODE, a CAPTCHA under a misleading 405) and the User-Agent gate (S3 buckets serving 403 unless the request carries an IGV-prefixed agent, which no browser can send). A fix for one does nothing for the other. This is a workaround with an expiry condition, not architecture — do not deepen it.

nvi.js

Unowned — on no candidate

js/nvi.js · 1271 lines · the largest file in the repo

The largest module on this map has no card in the review and no plan. That is worth naming rather than leaving as an omission. It is a lookup table for normalization vector indices, and it looks half-dead since the contact-map menu became self-describing.

Do not prune it. Old saved sessions and pasted URLs still hit it, silently — the same wire-format-as-user-contract argument that governs tier ④. If it ever gets a card, the gate has to come first, exactly as it did for candidate 5.

⑥ Render

ImageTileSource

Landed · candidate 1 · PR #433

js/imageTileSource.js (364) + js/imageTileCore.js (332)

Interface — four methods

getColorScale(displayMode)

setColorScale(scale, displayMode, state)

setThreshold(threshold, displayMode, state)

invalidate({ thresholds })

Tile retrieval itself is private (#tileAt) — callers ask for a repaint, not for a tile.

Hides

Cache keying — chromosome pair, bin size, unit, grid position, normalization, display mode; not pan position or pixel size, which affect where a tile is painted rather than what it contains.

Effective-normalization resolution. Colour-scale derivation including the auto-threshold percentile and its live-map divergence. The five display modes and the zoom-index translation the combining modes need.

Depth verdict — deep. This is the target shape, achieved. Four methods over two files of cache and colour logic; contactMatrixView.js went 1116 → 761 lines and the repo got its first rendering coverage, tests 65 → 164. When a later candidate asks "what am I aiming at?", the answer is this module.

InteractionHandler ← ContactMatrixView

Planned · candidate 7

js/contactMatrixView.js (845) · js/interactionHandler.js (514) · js/sweepZoom.js

Today: addMouseHandlers is 177 lines of closures and addTouchHandlers is 119. Gesture state — startX, mouseDown, lastTouch, pinch distance — lives in those closures, which means there is no test surface at all. The coordinator installs them by hand.

Target: the view forwards raw pointer events and holds no gesture state. InteractionHandler — already deep and already partly tested — grows onPointerDown/Move/Up, onWheel, onTouch*, and holds drag, double-click, pinch and sweep as explicit state. Testable with synthetic event objects. pinchZoom and _performWheelZoom de-duplicate on the way through.

Note the direction: this is not a new module. It is behaviour moving from a shallow module into a deep one that already exists and already talks to State only through translators. That makes it one of the cheaper cards, once candidate 6 has settled what a translator call looks like.

TrackPair / TrackRenderer / Tile

Speculative · candidate 11

js/trackPair.js (343) · js/trackRenderer.js · js/tile.js (18) · js/layoutController.js

Four fields, one concept. TrackPair reads this.tileX/tileY and carries a stray this.tile; TrackRenderer writes its own this.tile. Invalidation writes the renderer's field and the read path consults the pair's — a stale cache, sitting there.

Target: the pair owns tiles for both axes (tileFor(axis, genomicState), invalidate()); the renderer becomes canvas + blit and holds no cache field; doAutoscale comes out as a pure, tested function.

Marked speculative because the bug is real but the reshape may be larger than the payoff. Remember: track tile here has nothing to do with the image tile of the card above, despite the shared word — say which one you mean.

The shape, in one paragraph

A host calls one function and gets a registry. Config arrives by one of four doors, is decoded if it carries a wire format and then normalized exactly once, and reaches a browser as a resolved config no downstream module reinterprets. The browser owns identity and delegates everything else: canonical state lives behind a single chokepoint with translators around it and projections computed on read; data arrives through one load path with source adapters for file and live; pixels come from a tile source with a four-method interface; gestures are explicit state in a handler that speaks only translator. A coordinator fans changes out to widgets that are told when to refresh. Two event buses survive as published consumer surface with no internal traffic.

Five of those clauses are true today. The registry, the decoder, the tile source, the URL mapper and the event buses have landed. Normalize-once is being built now. The chokepoint's back door, the single load path, and gestures-as-state are ahead — and track tiles may never be worth doing.

Keeping this current

Revise, do not regenerate — the same convention the review runs on. A regenerated map loses the reasons, and the reasons are the part that took the work.

When a candidate lands: flip its card's state badge and border to landed, flip its node's classDef in the map, replace the "target" half of the card with what actually shipped (including where it differed from the plan — candidate 2 kept the bus it was named for, and that is the most useful sentence on its card), and move the loose ends into a closing note with their issue numbers.

When a card's shape changes before it lands: edit the target half in place. This document is allowed to be wrong about the future; it is not allowed to be wrong about the present.

When a new module appears that no candidate predicted: give it a card and mark it unowned, like nvi.js. An honest gap beats a tidy omission.

The header line carries the branch and snapshot date. Update it on every edit — a map with a stale date is a map people stop trusting, and a map people stop trusting is worse than none.
