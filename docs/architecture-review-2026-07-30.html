1 · Lift the tile pipeline out of the contact matrix view

Landed · PR #433 Strong in-process

js/contactMatrixView.js · js/colorScale.js · js/ratioColorScale.js

Before — shallow
After — deep
Problem
All the pure tile logic — key derivation, grid math, B-zoom translation, percentile heuristics, cache eviction — is trapped inside async canvas-bound methods reachable only through a live browser.
Solution
Move it behind a TilePipeline interface that takes zoom data and canonical state and returns an image tile; the view keeps only sizing, blitting and the spinner.
  • leverage: one interface replaces 7-param getImageTile and checkColorScale
  • locality: cache invalidation stops being open-coded in 3 files
  • the eviction bug becomes testable — imageTileCacheKeys is never pushed to, so the cache grows unbounded
  • interface stops lying: zoomIn() declares 0 params, is called with 3
  • first rendering tests in the repo
Outcome — merged ecd44d9

Landed as js/imageTileSource.js plus a pure core in js/imageTileCore.js. Named ImageTileSource, not TilePipeline — the codebase already said image tile, and tile alone means the 1D track tile.

contactMatrixView.js 1116 → 761 lines. Tests 65 → 164. Four phases, thirteen commits: extract six pure functions in place, assemble the module, switch the view over, fix the cache.

Three things the card did not predict:

  • tilesFor is an async generator. An array return would have blanked the viewport until the slowest fetch resolved — the old loop painted each tile as it resolved.
  • The cache fix was not one line. Adding the missing push while honouring the declared limit of 8 would have traded a leak for thrashing: that 8 assumes a 640×640 viewport (4 tiles), but 1000×1000 spans 9 and 1920×1080 spans 12. The limit became a floor — retain max(cacheLimit, tilesInView × 2).
  • Rasterization is testable only because the pure core takes a plain {width, height, data} buffer. Tests run in bare Node with no canvas.

Known gap: nothing tests the seam between ImageTileSource and ContactMatrixView. The tests cover the source; the view is DOM-bound, so its wiring is verified only by manual dev/ harness runs.

Bugs surfaced and deferred: #426, #430, #431, #432. #425 was fixed en route and is the root cause of #372, open since 2022.

Problem
On the per-browser bus, every published event has zero subscribers and every subscription has zero publishers — the two sets are disjoint. Meanwhile the coordinator hand-forges event-shaped object literals and calls receiveEvent directly, so receiveEvent is two interfaces wearing one name.
Solution
Delete browser.eventBus, the 11 dead subscriptions and 4 dead publishes; replace each receiveEvent({type,data}) call with a named method on the receiving module. Keep EventBus.globalBus — it's exported from js/index.js and Spacewalk/juicebox-web may consume it.
  • deletion test: complexity vanishes, it does not move
  • locality: one place to look when a widget doesn't refresh
  • removes the forged pseudoEvent in RenderCoordinator
  • hicResolutionSelector.receiveEvent has no caller at all — gone
  • EventBus.hold/release have no callers — gone
Verify the four globalBus event names against juicebox-web and Spacewalk before touching them — no subscriber exists in this repo and there is no recorded contract for them.

3 · Collapse the pass-through modules around HICBrowser

Next Strong deletion test

js/browserUIManager.js · js/renderCoordinator.js · js/hicBrowser.js (24 forwarding members)

Before — six thin bands per call
caller
browser.update() 1 line
renderCoordinator.update() re-entrancy queue
browser.startSpinner() 1 line
contactMatrixView.startSpinner() DOM
browser.ui.getComponent('x') Map lookup
widget work happens

Also: activeDataset/activeState and dataset/state are two accessor vocabularies used inside one render pass.

After — two bands
caller
browser.update() re-entrancy queue + spinner counting + fan-out widgets held as named fields
widget work happens

One accessor vocabulary. Spinner counting owned in one module.

Problem
BrowserUIManager is a stringly-typed Map with one method, and 4 of its 11 entries are never retrieved. RenderCoordinator's body is entirely this.browser.*; the browser re-exposes all of it as identical passthroughs. Neither adds an interface — they add a hop.
Solution
Delete BrowserUIManager; hold widgets as named fields built by a createWidgets(browser) function. Fold RenderCoordinator's re-entrancy queue back into HICBrowser.update and drop the duplicate spinner hop. Drop the 14 notify* one-liners and 10 back-compat accessors.
  • deletion test: ~120 lines vanish with no behaviour change
  • interface shrinks: 62 browser members → ~38
  • stringly-typed lookup becomes field access
  • fixes nesting of spinner counts under rapid drag
  • keep BrowserCoordinator — deleting it would push 300 lines back and make the god object real again

4 · Move the gesture state machines behind InteractionHandler

Open Worth exploring in-process

js/contactMatrixView.js (addMouseHandlers, addTouchHandlers) · js/interactionHandler.js · js/sweepZoom.js

Before
After
Problem
Gesture state lives in let closures inside 296 lines of the view, so drag, double-tap and pinch have no test surface — while the module that already owns gesture semantics sits directly underneath and is the best-tested one in the repo.
Solution
The view forwards raw pointer/touch/wheel events; InteractionHandler holds the gesture state explicitly and keeps routing to State translators.
  • the interface is the test surface: synthetic events in, state out
  • locality: gesture semantics stop straddling two modules
  • de-duplicates ~70 near-identical lines in pinchZoom / _performWheelZoom
  • would have caught const yLocus = { xLocus } — object-wrapped instead of spread
  • extends the setView chokepoint discipline to the last unguarded paths

Problem
Eight of ten StateManager methods are field get/set, re-wrapped again by ten HICBrowser accessors — browser.state is a two-hop pass-through. The one thing a state manager exists for is bypassed by its own owner: two browser setters write stateManager.activeState directly, commented "bypasses validation".
Solution
Move the three real behaviours — the setState pixel-size floor, getSyncState, canBeSynched — onto State, which already owns sync, clone and setView. The browser holds three plain fields.
  • locality: the mutation invariant has one enforcer, not two
  • lands in the module with the repo's strongest tests
  • closes the "bypasses validation" back door
  • bulk replacement stops being a second, undocumented path
  • cheapest coverage win available today
Extends the discipline recorded in docs/state-manipulation.md (issue #411) rather than contradicting it. That doc would need its "Bulk replacement" and "Where to look in code" sections updated.

7 · Give the track tile one owner

Open Speculative in-process

js/trackPair.js · js/trackRenderer.js · js/tile.js · js/layoutController.js

Before — four fields, one concept
After — cache owned by the pair
Problem
Four fields hold the same track tile across two modules; invalidation on colour and data-range change writes the renderer's field while the read path consults the pair's. Meanwhile LayoutController constructs track pairs and mutates browser.trackPairs, so ordering is derived by parsing CSS style.order back out of the DOM.
Solution
The pair owns the tile cache for both axes; the renderer keeps canvas and blitting; layout keeps DOM sizing. Track ordering becomes a field on the pair, not a CSS read-back.
  • locality: one owner for the cache, one invalidation call
  • fixes stale tiles after colour / data-range change
  • layout stops being the model for track order
  • doAutoscale is pure and unexported — export and test it
  • speculative because it touches igv-owned objects; scope with care

3 · Collapse the pass-through modules around HICBrowser start here

The original plan was candidate 2 first, then 3, then 1. That is now stale: candidate 1 went first because it was the direction asked for, and candidate 2 turns out to be issue #414, filed months before this review — the event-bus findings belong there rather than here.

So 3 is next. It is the remaining pure subtraction: BrowserUIManager is a stringly-typed Map with one method and four never-retrieved entries, RenderCoordinator's body is entirely this.browser.*, and 24 members of HICBrowser exist only to forward. The deletion test answers "complexity vanishes," not "complexity moves." Roughly 120 lines with no behaviour change.

Candidate 1 removed two of that work's obstacles already: hicBrowser.repaintMatrix no longer reaches into another module's cache, and the tmp = x; x = tmp no-op in init is gone.

After 3: 4 is the largest remaining deepening — ~300 lines of gesture closures with no test surface, sitting directly above the best-tested module in the repo.
