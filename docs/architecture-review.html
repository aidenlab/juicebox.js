Before scoping any card — the consumer lens

juicebox.js is an embeddable component. HICBrowser is not exported from js/index.js, but hosts get instances from init(), so its whole instance surface is public in practice. "No callers in js/" is half a finding: check the manifest, js/publicApi.js, and ADR-0003. The review was first written without this, and two cards were wrong because of it. Every card below carries a Consumer impact block for that reason.

The before / after diagrams

Every card makes the same two-panel argument: left is today, right is proposed. The visual language is identical across all cards, whether the panel is an SVG or a mermaid graph.

Red fill — the problem. Tangled code, dead code, or a field that lies.
Red arrow — leakage. Something reaching across a boundary it should not know about.
Dark navy block — the deep module. Small interface on top, substantial logic hidden inside. This is the goal state in every card; it only ever appears on the right.
Dashed gray line — a seam. The new boundary being introduced, and the line the tests will run against.
White box — an ordinary module. Unremarkable, left alone.
Green — pure, tested, or extracted-and-now-testable. Free functions with no I/O and no framework.

The shorthand: how much red on the left, how much navy on the right. That is the whole picture. Card 10 is the clearest instance — three red near-clones become one navy interface.

Anatomy of a card
  1. Title + three badges — the claim and its standing.
  2. Monospace file list — every file the work touches. A rough proxy for blast radius.
  3. Before / after panels — the argument, in the visual language above.
  4. Problem / Solution pair — the same argument in two sentences. If you read nothing else on a card, read this.
  5. Bulleted payoff list — why it is worth it. Recurring terms: leverage (one interface replaces many call shapes), locality (one place to look instead of several), the interface is the test surface (it becomes testable without standing the whole system up).
  6. Amber box, when present — a caveat to check before starting.
  7. When it lands — the card leaves the backlog and becomes one row in Landed. What the work found goes in its ADR.

Open candidates

10 · One dataset-load path — this is the live-map seam

Tracked · #581 Worth exploring ports & adapters

js/dataLoader.js · js/hicDataset.js · js/imageTileCore.js

Before — three near-clones
loadHicFile · 186 lines
shield · label · spinner · Dataset.loadDataset · Genome · state ladder · nvi lookup · sync · notify ×5 · try/catch/finally
loadLiveContactMap · 78 lines
shield · label · HiCDataset · Genome · state ladder (duplicated) · notify ×4
loadHicControlFile · 66 lines
shield · label · Dataset.loadDataset · its own catch and alert · notify ×2
reaches out to: browser.userInteractionShield, contactMapLabel and browser.genome
After — collapsed
loadMap(source, role) — one interface
source adapter: .hic file | live contact map
role: primary | control
one error contract · one spinner/shield discipline · one notify sequence
chooseInitialState(config) — pure
the State.default / parse / fromJSON ladder, extracted and tested
classifyTrack(config) — pure
1D/2D dispatch incl. the .txt/.txt.gz case, extracted and tested
DOM labels and shield move to the coordinator
Problem
Three load paths share ~60% of their bodies but diverge in error handling, and the two genuinely pure decisions inside them — initial-state selection and the 1D/2D track heuristic — are trapped in long async methods with network, DOM and module globals in the way.
Solution
One loadMap(source, role) interface with two source adapters; lift the two pure decisions out as free functions.
  • two adapters justify the seam: .hic file and live contact map
  • locality: one error contract, one shield-and-spinner discipline, one notify sequence
  • the pure ladders become testable with object literals
  • the data module stops writing DOM labels
  • one place for the post-load sync step — the live path already gets it wrong, leaving a one-sided sync edge (#638)
Consumer impact — three named entry points must survive
loadHicFile (both apps), loadHicControlFile (juicebox-web) and loadLiveContactMap (Spacewalk) are three distinct public calls with three signatures. Collapsing them onto one internal loadMap(source, role) is fine — the three named methods on HICBrowser are not optional, and their argument shapes are contract.

Spacewalk passes {liveContactMap, name, locus}; juicebox-web passes {url, name, nvi, ...}. All three are declared in js/publicApi.js; removing one fails test/testPublicApi.js.
Read this before scoping — what the card's title hides

This candidate is the live contact map seam, and the seam was built as an expediency: the goal was to make a live map, streamed from hic-straw, look to juicebox.js like a file-based .hic map. The disguise is deliberate and mostly successful — but "one load path" means deciding whether the disguise was the right call, not just deduplicating three method bodies.

The debt spans three repos. The core work lives in hic-straw (which is not in the architecture review at all) and in Spacewalk; what reached juicebox.js is a thin adapter. Narrow, but it leaks in exactly three places:

  • js/hicDataset.js — isLive is set from config and datasetType derived from it. Both are consumer contract; Spacewalk branches on dataset.isLive.
  • js/imageTileCore.js — autoThreshold takes the 75th percentile instead of the 95th and clamps to 1 for live maps. A genuine rendering divergence, not an adapter detail: the disguise does not hold here, and any change to the load path has to keep this branch reachable.
  • js/dataLoader.js — loadLiveContactMap as a separate path, with the state ladder duplicated from loadHicFile.

#471 settled the datasetType vocabulary to 'live' | 'hic' | 'unknown'. Whether the coordinator payload should carry it at all is still this card's question.

7 · Move the gesture state machines behind InteractionHandler

Tracked · #580 Worth exploring in-process

js/contactMatrixView.js (addMouseHandlers, addTouchHandlers) · js/interactionHandler.js · js/sweepZoom.js

Before
After
Problem
Gesture state lives in let closures inside ~300 lines of the view, so drag, double-tap and pinch have no test surface — while the module that already owns gesture semantics sits directly underneath and is the best-tested one in the repo.
Solution
The view forwards raw pointer/touch/wheel events; InteractionHandler holds the gesture state explicitly and keeps routing to State translators.
  • the interface is the test surface: synthetic events in, state out
  • locality: gesture semantics stop straddling two modules
  • de-duplicates ~70 near-identical lines in pinchZoom / _performWheelZoom
  • would have caught const yLocus = { xLocus } — object-wrapped instead of spread
  • extends the setView chokepoint discipline to the last unguarded paths
Consumer impact — indirect, via two crosshair paths
No consumer touches the mouse or touch handlers, so the refactor surface itself is clear. But the gesture code being moved is what fires both crosshair paths Spacewalk depends on: setCustomCrosshairsHandler (registered at juiceboxPanel.js:180) and the DidHideCrosshairs event (contactMatrixView.js:550). Both must still fire, with the same payloads, after the state machines move.

11 · Give the track tile one owner

Tracked · #582 Speculative in-process

js/trackPair.js · js/trackRenderer.js · js/tile.js · js/layoutController.js

Before — four fields, one concept
After — cache owned by the pair
Problem
Four fields hold the same track tile across two modules; invalidation on colour and data-range change writes the renderer's field while the read path consults the pair's. Meanwhile LayoutController constructs track pairs and mutates browser.trackPairs, so ordering is derived by parsing CSS style.order back out of the DOM.
Solution
The pair owns the tile cache for both axes; the renderer keeps canvas and blitting; layout keeps DOM sizing. Track ordering becomes a field on the pair, not a CSS read-back.
  • locality: one owner for the cache, one invalidation call
  • fixes stale tiles after colour / data-range change
  • layout stops being the model for track order
  • doAutoscale is pure and unexported — export and test it
  • speculative because it touches igv-owned objects; scope with care
Consumer impact — the track pair is published shape
juicebox-web calls browser.layoutController.removeTrackXYPair(pair), and gets that pair from the global-bus TrackXYPairLoad / TrackXYPairRemoval payloads — reading data.track.config.format and data.track.name off it, keying its track index off pair.browser, and handing the same object back.

So TrackPair.track, TrackPair.browser, its config.format, and the two event payloads are all contract. "The pair owns the tile cache" is safe; renaming .track or changing what the events carry is not. Spacewalk separately calls layoutController.getContactMatrixViewport().

Defects surfaced incidentally

Found while scanning, not themselves the recommendation. Four of the original five are fixed or went with the code they lived in. One is still live, checked against v4.4.0:

Session compression truncates any character above U+00FF — not filed

encodeSessionString (js/sessionCodec.js) hands raw JSON to igv-utils' BGZip.compressString, which does charCodeAt into a Uint8Array — a mod-256 truncation. The payload carries user free text (captions, dataset and track names), so a curly quote or an em-dash yields a shared link that restores with the wrong characters.
