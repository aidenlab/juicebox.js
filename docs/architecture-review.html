Correction — 6 August 2026 · read first

This review was written without a consumer lens, and that produced wrong verdicts. juicebox.js is an embeddable component, not an application. It is consumed by juicebox-web and Spacewalk — and, being MIT and published, by embedders we cannot see. HICBrowser is not exported from js/index.js: hosts get instances from init(), so the entire browser-instance surface is public in practice and declared nowhere.

The consequence: the deletion test cannot be answered by grepping js/. Doing so returns "no callers" for members two shipped apps depend on. Two cards asserted exactly that and were wrong — candidate 2 ("every published event has zero subscribers"; Spacewalk subscribes one) and candidate 3 ("31 members carry zero behaviour"; five are consumer API).

It has already cost a real regression: juicebox-web has subscribed to MapLoad since PR #406 shipped in v3.1.0 (Dec 2025) removed the publish. Silently dead for eight months.

Every card below now carries a Consumer impact block, measured against both checkouts at v3.6.2. The surface itself is ADR-0003. Read it before scoping any candidate.

Progress

Candidate 3 is done — 99c297b / 18ac88b (issue #467). browserUIManager.js and renderCoordinator.js deleted, createWidgets.js added; 14 notify* forwarders gone. Its member-count target was retired, not met — see Consumer impact on that card.

Candidate 1 is done — merged as ecd44d9 (PR #433, issue #428). contactMatrixView.js 1116 → 761 lines; tests 65 → 164, the first rendering coverage in the repo.

Candidate 2 is tracked elsewhere as issue #414, filed May 2026. Its findings live on that issue.

Eight candidates are open. Recommended next task.

Always gray, so it reads as noise. It isn't — it is the best single predictor of how the work will feel.

The before / after diagrams

Every card makes the same two-panel argument: left is today, right is proposed. The visual language is identical across all cards, whether the panel is an SVG or a mermaid graph.

Red fill — the problem. Tangled code, dead code, or a field that lies.
Red arrow — leakage. Something reaching across a boundary it should not know about.
Dark navy block — the deep module. Small interface on top, substantial logic hidden inside. This is the goal state in every card; it only ever appears on the right.
Dashed gray line — a seam. The new boundary being introduced, and the line the tests will run against.
White box — an ordinary module. Unremarkable, left alone.
Green — pure, tested, or extracted-and-now-testable. Free functions with no I/O and no framework.

The shorthand: how much red on the left, how much navy on the right. That is the whole picture. Card 3 is the clearest instance — six thin red bands, one per hop, become two.

Anatomy of a card
  1. Title + three badges — the claim and its standing.
  2. Monospace file list — every file the work touches. A rough proxy for blast radius.
  3. Before / after panels — the argument, in the visual language above.
  4. Problem / Solution pair — the same argument in two sentences. If you read nothing else on a card, read this.
  5. Bulleted payoff list — why it is worth it. Recurring terms: leverage (one interface replaces many call shapes), locality (one place to look instead of several), the interface is the test surface (it becomes testable without standing the whole system up).
  6. Amber box, when present — a caveat to check before starting.
  7. Green box, when present — the outcome, written after the work landed. Includes what the card failed to predict.
Suggested reading order

Not front to back. The cards are a backlog, written to be read when you reach them.

  1. The green Progress box at the top — where things stand.
  2. The Next task section — one recommendation.
  3. That one card. Nothing else.

Browser lifecycle & wiring

3 · Collapse the pass-through modules around HICBrowser

Next Strong deletion test

js/browserUIManager.js · js/renderCoordinator.js · js/hicBrowser.js (31 forwarding members)

Before — six thin bands per call
caller
browser.update() 1 line
renderCoordinator.update() re-entrancy queue
browser.startSpinner() 1 line
contactMatrixView.startSpinner() DOM
browser.ui.getComponent('x') Map lookup
widget work happens

Also: activeDataset/activeState and dataset/state are two accessor vocabularies used inside one render pass.

After — two bands
caller
browser.update() re-entrancy queue + spinner counting + fan-out widgets held as named fields
widget work happens

One accessor vocabulary. Spinner counting owned in one module.

Problem
BrowserUIManager is a stringly-typed Map with one real method, and 5 of its 13 entries are never retrieved. RenderCoordinator's body is entirely this.browser.*; the browser re-exposes all of it as identical passthroughs. Neither adds an interface — they add a hop.
Solution
Delete BrowserUIManager; hold widgets as named fields built by a createWidgets(browser) function. Fold RenderCoordinator's re-entrancy queue back into HICBrowser.update and drop the duplicate spinner hop. Drop the 13 notify* one-liners and the back-compat accessors.
  • deletion test: ~120 lines vanish with no behaviour change
  • HICBrowser has 80 members; 31 forward without adding behaviour — 18 delegations plus 14 notify*. Only the notify* half was deletable: five of the delegations are consumer API. Delivered 80 → 65 (#467)
  • stringly-typed lookup becomes field access
  • fixes nesting of spinner counts under rapid drag — update() and renderTrackXY() both start one, and the inner finally stops the shared spinner while the outer is still running
  • dead on arrival: RenderCoordinator.init() duplicates a constructor line; getCallbacksFor() and listComponents() have no callers
  • keep BrowserCoordinator — deleting it would push 300 lines back and make the god object real again
Two calling conventions are live simultaneously and both must keep working through the change: annotationWidget.js:187 calls browser.notifyTrackState2D, while hicColorScaleWidget.js:183 calls browser.coordinator.onBackgroundColorChange directly.
Consumer impact — the member count below is not a target
The "31 carry zero behaviour" figure counts five members that are consumer API. loadHicFile (both apps), loadTracks and loadHicControlFile (juicebox-web), loadLiveContactMap and parseGotoInput (Spacewalk). Four of them have no internal callers at all — they exist only for hosts, so deleting them publishes dataLoader and interactions instead of removing a hop.

The notify* half was safe and is done: neither app called one. Delivered 80 → 65, not 80 → ~49; the target is retired, see #467. Also must survive: reset, config, layoutController, eventBus, coordinator (ADR-0002).

4 · Give the browser registry an owner

Open Strong in-process

js/createBrowser.js · js/init.js · js/session.js · js/dataLoader.js · js/layoutController.js · js/globals.js

Before — one registry per page
After — one registry per host container
Problem
The set of live browsers is a module-level let in createBrowser.js:14, scoped to the page rather than the embed. A host calling hic.init() twice has its first browser's DOM removed by the second call, and syncBrowsers() cross-joins every browser on the page regardless of container.
Solution
An object returned by init() owns its browsers, its current-browser pointer, its sync group and its teardown. The pairing rule comes out as a free function over a list.
  • this is issue #384, open and previously undiagnosed
  • locality: "which browsers exist" has one owner instead of a file-scope variable six modules reach into
  • the interface is the test surface: today no test constructs a browser, because test N leaks into test N+1
  • gives dispose() a home — see candidate 8
  • plausibly also #280 — the sync race depends on which browser's fetch resolves first
Four page-scoped singletons ride along and must be scoped with it or deliberately left alone: the --hic-viewport-* CSS custom properties written to document.documentElement (layoutController.js:246), Globals.selectedGene, the Alert singleton re-bound per init(), and inProgressCache in contactMatrixView.js:723. The CSS variables are the hard one — two embeds cannot currently have different viewport sizes, and fixing that is a rendering change, not a lifecycle change.
Consumer impact — changes a public return type
Highest-exposure candidate on the list. juicebox-web uses every registry export: getCurrentBrowser (10 sites), getAllBrowsers, setCurrentBrowser, createBrowser, init; Spacewalk uses getCurrentBrowser. "An object returned by init()" changes what init resolves to — today a browser or a list of them, which both apps depend on. juicebox-web also reads getCurrentBrowser().config for {width, height}.

Do it additively: the owner object is new, and the four module-level functions stay, delegating to a default registry. Otherwise this is a major version, not a refactor.

8 · Give the browser a teardown that matches its construction

Open Worth exploring in-process

js/hicBrowser.js (constructor, reset) · js/createBrowser.js (deleteBrowser, deleteAllBrowsers) · js/layoutController.js · js/eventBus.js

Before — construction and teardown disagree
constructor installs 29 fields
rootElement → container removed ✓
InputDialog → appContainer leaked ✗
this.eventBus subscriptions never unsub ✗
globalBus subscriptions never unsub ✗
LayoutController's 4 fields not cleared ✗
reset() touches 7 of 29

Three teardown paths that do different things: reset(), deleteBrowser(), deleteAllBrowsers() — only one calls unsyncSelf().

After — one symmetric pair
constructor records what it installed
dispose() removes every element it appended unsubscribes both buses unsyncs from peers releases the registry slot
reset() = dispose + construct

One teardown. deleteBrowser and deleteAllBrowsers both call it.

Problem
The constructor appends elements outside rootElement's subtree — notably InputDialog into the app container — but every delete path removes only rootElement. Repeated init() / restoreSession() cycles accumulate orphaned dialogs, and no path unsubscribes from either event bus.
Solution
One dispose() on HICBrowser, symmetric with the constructor. reset() becomes dispose-then-construct; both free delete functions delegate to it.
  • locality: one place to add cleanup when a field is added to the constructor
  • a leaked InputDialog per session restore is real, reproducible growth
  • pairs with candidate 4 — a registry needs something to call
  • the unsubscribe gap is also recorded in issue #414
Consumer impact — redefines a method juicebox-web calls
juicebox-web calls browser.reset() and then, on the very next line, await browser.loadHicFile(config) on the same instance (initializationHelper.js:366-367).

"reset() becomes dispose-then-construct" breaks that if the browser it holds is invalidated or replaced. Either reset() keeps returning a usable browser of the same identity, or this needs a coordinated change in juicebox-web — decide which before writing code.

9 · Give the config schema one reader

Open Worth exploring in-process

js/createBrowser.js (setDefaults) · js/hicBrowser.js (constructor, init) · js/dataLoader.js · js/browserUIManager.js · js/urlUtils.js (fixDefaults)

Before — seven readers, no schema
After — normalize once, read everywhere
Problem
No file states what a config contains. Seven modules each interpret a subset and apply their own defaults, so the entry points have silently diverged: syncDatasets is honoured by createBrowserList but not createBrowser, and fixDefaults runs on the URL path but not on restoreSession — the documented public API.
Solution
One pure normalizeConfig at the entry, producing a resolved config. Downstream modules read fields and never default.
  • the interface is the test surface: config handling becomes object-literal-testable
  • the asymmetries become visible instead of spread across seven files
  • setDefaults is already pure — it just isn't exported
  • documents the config schema by being it
  • pairs naturally with candidate 5 — decode, then normalize
Consumer impact — the config object is the entry contract
The config passed to hic.init(container, config) is the most-used public surface there is: juicebox-web passes a full juiceboxConfig, Spacewalk passes {} and drives everything through restoreSession. A normalizeConfig that tightens validation will reject configs that work today.

Also: juicebox-web reads browser.config back off the instance, so the resolved config is observable too — normalising it changes what that read returns.

5 · One decoder for session and URL

Open Strong ports & adapters

js/urlUtils.js · js/session.js · js/hicState.js (parse/fromJSON/stringify) · js/dataLoader.js · js/createBrowser.js

Before — eight encodings, three write-only
blob:<BGZip> detection — written 3×
urlUtils.js:64 · :71 · :87 — same 4 lines, three error messages
state format detection — written 2×
dataLoader.js:112 · :233 — already drifted; one has no unknown-type branch

3 state decoders · 4 config decoders
parse · fromJSON · sync — extractConfig · decodeQuery · restoreSession · createBrowserList
no encoder at all for 4 formats
query config · track pipe-string · juicebox={},{} · juiceboxURL
State.stringify has zero callers — dead encoder, live decoder
After — one decode, adapters at the edge
decodeSession(input) — one interface
adapters: query string | session JSON | compressed blob | legacy state token
one error contract · one shortcut-expansion pass · one place a new format is added
sniffFormat(string) — pure
blob / data / JSON / legacy-token, extracted from three async wrappers

the parse / fromJSON / default ladder, one place, tested with literals
encodeSession — the missing inverse
round-trip becomes a property test: decode(encode(x)) === x
network I/O (bitly, file fetch) moves to the caller
Problem
There is no single parse. Eight encodings of the same seven canonical fields are decoded by three state decoders and four config decoders, with blob detection written out three times and state-format detection twice — the two copies have already drifted. extractConfig is async across ~90 lines of which two do I/O, so none of the format logic is reachable from a test.
Solution
One decodeSession interface with an adapter per wire format; lift format sniffing and the state-decode ladder out as pure functions; write the missing encoder so round-tripping is testable.
  • four adapters justify the seam — this is not a hypothetical one
  • leverage: adding a format touches one module instead of four
  • the pure ladders become testable with string literals — no network, no DOM
  • a round-trip property test is the single highest-value test this repo could add
  • save → restore is not currently the identity: the State constructor transposes axes when chr1 > chr2, which is reachable at runtime
docs/url.md documents a track pipe-string layout that does not match the parser (3 tokens vs the parser's 4; the param is track in the doc, tracks in the code at urlUtils.js:184). Decide which is authoritative before collapsing the decoders — juicebox-web may generate URLs against either reading. These are public, shareable URLs; a decoder change is a compatibility change.
Consumer impact — the wire format is a user-facing contract
restoreSession, compressedSession and toJSON are used by both apps. Beyond the call signatures, the encoded session format is public in a stronger sense than any method: users share sessions as URLs, so a link pasted last year must still decode. Round-tripping has to stay compatible in the decode direction even if the encoder changes.

The report already names this the strongest ADR opportunity, and it is right — but the reason is the external consumer, not the internal duplication. Write the ADR before the refactor, not after.

And the one thing a state manager exists for is bypassed by its own owner: restore skips every invariant setView enforces — no MAX_PIXEL_SIZE cap, no x/y clamp, resolutionChanged hardcoded true — and two browser setters write activeState directly, commented "bypasses validation".

Move the three real behaviours — the setState pixel-size floor, getSyncState, canBeSynched — onto State, which already owns sync, clone and setView. Restore becomes a translator like the others. The browser holds three plain fields.

  • closes the "bypasses validation" back door

  • unvalidated normalization on restore is plausibly issue #372
  • two independent scans reached this card — the second raised it from worth exploring to strong
Extends the discipline recorded in docs/state-manipulation.md (issue #411) rather than contradicting it. That doc's "Bulk replacement" and "Where to look in code" sections would need updating — bulk replacement stops being an exception and becomes a translator.

Spacewalk also reads dataset.isLiveContactMapDataSet and activeDataset.isLive, so the dataset objects have published shape as well.

Note this collides with #468, which proposes unifying the activeDataset/dataset vocabulary — both names are in use externally, so neither can simply win.

Problem
Three load paths share ~60% of their bodies but diverge in error handling, and the two genuinely pure decisions inside them — initial-state selection and the 1D/2D track heuristic — are trapped in 120-line async methods with network, DOM and module globals in the way.
Solution
One loadMap(source, role) interface with two source adapters; lift the two pure decisions out as free functions.
  • two adapters justify the seam: .hic file and live contact map
  • locality: one error contract — control-load failure currently leaves a stale "A:" label
  • the pure ladders become testable with object literals
  • the data module stops writing DOM labels
  • the post-load sync block is the race behind #280 — one path makes it orderable
Consumer impact — three named entry points must survive
loadHicFile (both apps), loadHicControlFile (juicebox-web) and loadLiveContactMap (Spacewalk) are three distinct public calls with three signatures. Collapsing them onto one internal loadMap(source, role) is fine — the three named methods on HICBrowser are not optional, and their argument shapes are contract.

Spacewalk passes {liveContactMap, name, locus}; juicebox-web passes {url, name, nvi, ...}. All three are declared in js/publicApi.js; removing one fails test/testPublicApi.js.
Read this before scoping — what the card's title hides

This candidate is the live contact map seam, and the seam was built as an expediency: the goal was to make a live map, streamed from hic-straw, look to juicebox.js like a file-based .hic map. The disguise is deliberate and mostly successful — but "one load path" means deciding whether the disguise was the right call, not just deduplicating three method bodies.

The debt spans three repos. The core work lives in hic-straw (which is not in the architecture review at all) and in Spacewalk; what reached juicebox.js is a thin adapter. Narrow, but it leaks in exactly three places:

  • js/hicDataset.js — isLive is set from config and datasetType derived from it. Both are consumer contract; Spacewalk branches on dataset.isLive.
  • js/imageTileCore.js — autoThreshold takes the 75th percentile instead of the 95th and clamps to 1 for live maps. A genuine rendering divergence, not an adapter detail: the disguise does not hold here, and any change to the load path has to keep this branch reachable.
  • js/dataLoader.js — loadLiveContactMap as a separate path, with the state ladder duplicated from loadHicFile.

Two live artefacts of the churn, both worth reading first: #471 (the datasetType vocabulary collision this seam created), and the fact that ADR-0003 cited a dataset flag named isLiveContactMapDataSet that exists in no repo — a rename that left a stale reference in a document written the same week.

1 · Lift the tile pipeline out of the contact matrix view

Landed · PR #433 Strong in-process

js/contactMatrixView.js · js/imageTileSource.js · js/imageTileCore.js

Problem
All the pure tile logic — key derivation, grid math, B-zoom translation, percentile heuristics, cache eviction — was trapped inside async canvas-bound methods reachable only through a live browser.
Solution
Move it behind an interface that takes zoom data and canonical state and returns an image tile; the view keeps only sizing, blitting and the spinner.
Outcome — merged ecd44d9

Landed as js/imageTileSource.js plus a pure core in js/imageTileCore.js. Named ImageTileSource, not TilePipeline — the codebase already said image tile, and tile alone means the 1D track tile.

contactMatrixView.js 1116 → 761 lines. Tests 65 → 164. Four phases, thirteen commits: extract six pure functions in place, assemble the module, switch the view over, fix the cache.

Three things the card did not predict:

  • tilesFor is an async generator. An array return would have blanked the viewport until the slowest fetch resolved — the old loop painted each tile as it resolved.
  • The cache fix was not one line. Honouring the declared limit of 8 would have traded a leak for thrashing: that 8 assumes a 640×640 viewport (4 tiles), but 1000×1000 spans 9 and 1920×1080 spans 12. The limit became a floor — retain max(cacheLimit, tilesInView × 2).
  • Rasterization is testable only because the pure core takes a plain {width, height, data} buffer. Tests run in bare Node with no canvas.

Known gap: nothing tests the seam between ImageTileSource and ContactMatrixView. The tests cover the source; the view is DOM-bound, so its wiring is verified only by manual dev/ harness runs.

Bugs surfaced and deferred: #426, #430, #431, #432. #425 was fixed en route and is the root cause of #372, open since 2022.

Consumer impact — checked, low
Spacewalk calls browser.contactMatrixView.update() (3 sites) and reads .ctx off it directly. Both survived this candidate; they are the reason contactMatrixView must keep that name and keep exposing a canvas context. No namespace impact. See ADR-0003.

Problem
Gesture state lives in let closures inside 296 lines of the view, so drag, double-tap and pinch have no test surface — while the module that already owns gesture semantics sits directly underneath and is the best-tested one in the repo.

11 · Give the track tile one owner

Open Speculative in-process

js/trackPair.js · js/trackRenderer.js · js/tile.js · js/layoutController.js

Before — four fields, one concept
After — cache owned by the pair
Problem
Four fields hold the same track tile across two modules; invalidation on colour and data-range change writes the renderer's field while the read path consults the pair's. Meanwhile LayoutController constructs track pairs and mutates browser.trackPairs, so ordering is derived by parsing CSS style.order back out of the DOM.
Solution
The pair owns the tile cache for both axes; the renderer keeps canvas and blitting; layout keeps DOM sizing. Track ordering becomes a field on the pair, not a CSS read-back.
  • locality: one owner for the cache, one invalidation call
  • fixes stale tiles after colour / data-range change
  • layout stops being the model for track order
  • doAutoscale is pure and unexported — export and test it
  • speculative because it touches igv-owned objects; scope with care
Consumer impact — the track pair is published shape
juicebox-web calls browser.layoutController.removeTrackXYPair(pair), and gets that pair from the global-bus TrackXYPairLoad / TrackXYPairRemoval payloads — reading data.track.config.format and data.track.name off it and handing the same object back.

So TrackPair.track, its config.format, and the two event payloads are all contract. "The pair owns the tile cache" is safe; renaming .track or changing what the events carry is not. Spacewalk separately calls layoutController.getContactMatrixViewport().

Problem
Inside this repo, every published event has zero subscribers and every subscription has zero publishers — the two sets are disjoint. Outside it they are not: Spacewalk subscribes DidHideCrosshairs on the per-browser bus, and juicebox-web subscribes four events on the global bus. See Consumer impact above. Meanwhile the coordinator hand-forges event-shaped object literals and calls receiveEvent directly, so receiveEvent is two interfaces wearing one name.
Solution
Delete the eight dead internal subscriptions and the two publishes nobody hears (DragStopped, DidShowCrosshairs); replace each receiveEvent({type,data}) call with a named method on the receiving module. Keep the browser.eventBus object itself and its DidHideCrosshairs publish — Spacewalk subscribes to it. Keep EventBus.globalBus and all four of its events: juicebox-web does consume them, measured.

  • locality: one place to look when a widget doesn't refresh
  • removes the forged pseudoEvent in RenderCoordinator
  • hicResolutionSelector.receiveEvent has no caller at all — gone
  • EventBus.hold/release have no callers — gone
  • the missing-unsubscribe half of this overlaps candidate 8
Tracked as issue #414 since May 2026 — the review did not discover it, and its findings have been added there. Verify the four globalBus event names against juicebox-web and Spacewalk before touching them: no subscriber exists in this repo and there is no recorded contract.
Consumer impact — the premise below is wrong
The disjointness claim holds only inside this repo. On the per-browser bus, DidHideCrosshairs is posted by contactMatrixView.js:488 and subscribed by Spacewalk (juiceboxPanel.js:147). Deleting browser.eventBus breaks it. On the global bus juicebox-web subscribes four events — GenomeChange (2 sites), BrowserSelect, TrackXYPairLoad, TrackXYPairRemoval — so "may consume it" is measured fact, not a hedge.

What is dead: all eight internal subscriptions (their events are never posted — they moved to the coordinator), plus DragStopped and DidShowCrosshairs, posted with no subscriber anywhere.

Already broken: juicebox-web subscribes MapLoad on the per-browser bus, which this library stopped posting in PR #406 (v3.1.0, Dec 2025) — dead for eight months, silently. Revised scope on #414. See ADR-0003.

Defects surfaced incidentally

Found while scanning, not themselves the recommendation. All verified against source at 7d9fd11. None are filed yet.

State.default() passes six arguments to a seven-parameter constructor

hicState.js:500 — new State(0, 0, 0, 0, 1, "NONE") against (chr1, chr2, zoom, x, y, pixelSize, normalization). One dropped zero, so the arguments shift: y = 1, pixelSize = "NONE" → parseFloat → NaN → coerced to 1, normalization = undefined → 'NONE'. The coercions hide it: the state is valid, just wrong. Every default view opens one bin below the origin on the y axis. Four call sites in dataLoader.js. Candidate 6 would move this code — file it first.

browser.toJSON() returns the string "{}", not an object

hicBrowser.js:903 — when a browser has no dataset. session.js:11 pushes it into the browsers array, and on restore setDefaults assigns properties to a string primitive. Saving a session while any browser is empty produces a session that cannot be reloaded.

expandURL repairs only the first brace pair — candidate cause of #283

urlUtils.js:372 — replace("{", "%7B") with a string pattern replaces one occurrence. The format it repairs, juicebox={…},{…}, has one pair per browser, so any multi-browser bit.ly link comes back malformed from browser 2 on.

Session compression truncates any character above U+00FF — candidate cause of #283

session.js:34 → BGZip.compressString, which does charCodeAt into a Uint8Array — a mod-256 truncation. The payload includes user free text (the caption scraped at session.js:19, dataset and track names). A curly quote or em-dash yields a permanently bad shared link, and nothing round-trips the blob before shortening it.

test/testURL.js:57 makes a live network call to bit.ly on every npm test

No fetch mock exists. CI is one bit.ly outage away from red, and the test is the only guard on the expandURL path above.
